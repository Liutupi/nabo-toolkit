# 固定口令的本人模板实验

此目录保留宿主C11探针及共享的整数声学核心。`features.c`、`matcher.c`已由F3离线语音候选直接编译使用，避免维护两份算法；设备任务、保存和页面适配在`firmware/main/tk_voice*`。它没有预训练中文模型、词典或语义识别能力，必须由使用者为每个编号录入自己的示例。编号只是模板标签；程序不会读取或匹配口令字符串。宿主合成实验不能证明真实口令识别率、嘈杂环境表现、耗电或C3实时性，实际验收另见HANDOFF与VALIDATION。

## 模板匹配纯核

`matcher.c/.h`对固定维数的声学特征序列执行流式DTW：每帧12维有符号整数，输入前端Q8输出除16量化成Q4的int8；每个词最多3个本人示例，最多7词。每个示例最多48个语音帧，查询最多96帧，每帧20ms。因此模板最多0.96秒语音、查询最多1.92秒语音；过长明确拒绝，不截断后冒充匹配。较长口令需要后续明确的、有边界的时长归一实验。

DTW使用12维L1均值、首尾完整对齐、单行成本与路径长度，不保留整段查询特征。候选的时间长度必须在录入示例的0.5–2倍内。同词多个示例取最低距离；不同词再比较绝对距离与差距。超过距离阈值、候选过近、完全平分、静音、太短、过长和没有录入模板都拒绝。距离不是概率或置信度。默认距离18、差距4仅为可调整的实验初值，未用真实录音校准。

前端/VAD决定`voiced`；`voiced=false`的帧不推进DTW。全零特征不自动当静音，因为去掉能量系数后的有效声音也可能接近零。模板录入者须只提供经过同一前端、同一量化和相同VAD规则的语音帧；不可将合成用例当作已录入真人数据。查询期间模板bank必须保持不变。

纯核无malloc、浮点或PSRAM。7×3×48×12模板bank、所有DTW行与独立48帧临时录入缓冲合计小于16KiB。设备录入与识别互斥，工作区把matcher与录入缓冲放在union中；探针用实际类型测量该布局，再加4096B前端、640B PCM与7个槽计数，总量必须小于20KiB，不再使用旧版6KiB前端预留的估算。宿主64位布局预计19968B；设备实际`sizeof(workspace_t)`须由固件构建及运行记录单独核验。这不是C3链接后代码大小、任务栈深度或实时运行的验收。

## 仅运行纯核宿主测试

需要Python、宿主C11编译器`cc`和binutils的`size`，无需ESP-IDF、不连接工牌：

```text
python tools/voice_probe/test_matcher.py
```

测试用连续的合成声学系数轨迹检查两倍拉伸、压缩、小扰动、VAD静音、未知序列、反序声学变化、同词多模板、跨词歧义、输入长度/地址边界、量化与RAM/代码预算。这些只检验算法和边界，不是自然语音测试。

## PCM前端与真实录音实验

`features.c/.h`每20ms处理320个16kHz单声道16bit采样，使用512点整数FFT、20个log2 mel滤波带和12个去c0的DCT系数；常量由`gen_tables.py`在宿主生成，运行时不含浮点或malloc，工作区4096B。`test_features.py`检查静音/DC、频带、增益、极值、独立DFT参照和表的可再生性；参照误差门槛仅针对指定宽带样本，不能推广所有音频。`test_pipeline.py`检验生成的16bit采样实际经过前端和DTW的组合，不是麦克风或真人识别率测试。

`python -m unittest discover -s tools/voice_probe -p 'test_*.py' -v`运行全部24项探针检查。`measure.py`是先前保留的“精确旧app对象+强制算法引用”的链接量体积工具，不是完整候选固件构建或刷写入口；当前F3源码已变化，不能再将旧app作为其baseline运行并套用旧结果。

设备候选采用300ms安静校噪、300ms尾静音及3秒墙钟上限，按需录入/查询，非持续唤醒。本人录入、独立重复说词、静音及非目标语音的留出实测需分别记录每词漏识、误识、拒绝、混淆、时延和资源数据。使用方法见[中文](../../docs/VOICE.zh_CN.md)和[English](../../docs/VOICE.md)。
