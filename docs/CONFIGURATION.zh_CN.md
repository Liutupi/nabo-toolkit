# 快捷键和名片配置（F2/F3）

公开入口：[NABO工具箱配置](https://liutupi.github.io/nabo-toolkit/)；顶部“名片 / Wi-Fi 二维码”可直达编辑区。新版默认组使用最新在线页面，或独立离线配置补充包 [`nabo-toolkit-config-shortcuts-20261028.zip`](https://github.com/Liutupi/nabo-toolkit/releases/download/v0.3.0-f3-dev3/nabo-toolkit-config-shortcuts-20261028.zip)；补充包已追加到[原v0.3.0-f3-dev3 Release](https://github.com/Liutupi/nabo-toolkit/releases/tag/v0.3.0-f3-dev3)。

**发布边界**：上述在线页和命名补充包当前仍为f8b8ad8六组快照，包含抖音（HANDOFF25）。当前本地源码另有待发布的五组/媒体/息屏候选，其新界面与显示行为尚未上线或安装到工牌。

原固件ZIP及 `nabo-toolkit-config-offline.zip` 保留发布时的页面/默认组，不会随着在线页自动更新。要使用“使用新版默认快捷键（保留名片）”按钮，请选择最新在线页或上述新命名补充包；其元数据为 `config-shortcuts-manifest.json`，独立校验文件为 `CONFIG_SHORTCUTS_SHA256SUMS.txt`。这是仅配置补充，不含新固件，不替换原八个发布资产。全部11个Release资产已匿名下载，字节/SHA256与本地相等，原八个哈希不变；新ZIP的13个成员均通过manifest校验。最新Pages部署的manifest及11个可访问文件也通过匿名HTTP200与字节/哈希核验。

开发入口是现有 `game-art/toolkit/prototype/config.html`，无需联网。页面分开提供浏览器保存和USB工牌读写：只有点击“写入工牌并核对”才向所选串口写入。**F2历史验收：dev2曾授权app-only安装，真实USB保存/读回/两轮重启保留和20次连续读回通过；自定义文字/名片/扫码及成功保存后断电保留也通过。浏览器真实权限弹窗和传输中拔线仍待验收。**

当前工牌已安装F3 dev3；F2协议沿用。在Chrome/Edge打开本地页面或localhost服务，用数据线接工牌，点“连接工牌”选择重新枚举的正确USB串口。可以先“从工牌读回”，再编辑并“写入工牌并核对”。先释放串口监视器；打开端口可能重启，USB复位后可能需要重新连接页面。页面不自动选择/打开串口；中断/超时后先读回核对，不自动重写。

可编辑1–6组快捷键以及1–3张名片。本地候选页每组按实体从上到下显示上/下/OK；已公开快照仍是早先排布。JSON保留原up/ok/down字段。录键或手动勾选修饰键支持左右Ctrl/Shift/Alt/Win；Mac/iPhone与Windows/安卓两套分别保存。可清空某一平台绑定；完全未设置的键不发HID。会议、PPT、拍照及候选的音乐/抖音媒体键固定，不在此编辑。默认配置来自当前作者维护的 `tk_hid.js`，既有个人配置不自动覆盖。

| 字段 | 限制 |
|---|---|
| 根结构 | `v:1`，必须同时有 `groups`、`cards`；拒绝未知字段、重复键 |
| 组名 / 键名 | 最多各 8 个 Unicode 字符；组名非空 |
| 组合键 | `{mod,key}`；mod 0–255，key 为0或4–115，修饰键单独组合使用 key0；平台项可为null |

键名从旧页面6字限制扩为8字，以容纳原默认“播放 / 暂停”；名片名字从旧页面16字扩为24字，保留默认 `github.com/Liutupi`。这些是F2阶段的输入限制修正；后来用户要求的新版分组见上表，协议和字段上限不变。配置导入、浏览器保存、USB写入使用同一验证规则；导出为紧凑JSON，确保可原样导入。Wi-Fi二维码内容由页面转义生成，**密码会明文存入工牌/备份**，分享文件前删除私人内容。

固件的紧凑中文备用字库来自同一现有思源黑体，中日韩统一表意文字及常用标点共21,281字形，16px/1bpp，直接从Flash读取，按显示字号缩放。它不占整幅字形位图RAM；非字库字符用方框代替。F3已接入原七条动画和专用语音，用户验收见HANDOFF22。

## USB 协议

每行ASCII，以LF结束；CRLF亦可。数据按UTF-8 JSON计算长度和CRC32（IEEE，初值/末异或均0xffffffff），每段原始数据≤48字节，标准规范base64≤64字符。每段收到确认后再发下一段。

| 请求 | 成功回复 |
|---|---|
| `>tk.cfg.abort` | `tk.cfg.aborted`，取消未提交的传输 |
| `>tk.cfg.begin <字节数>` | `tk.cfg.ready <字节数>` |
| `>tk.cfg.data <base64>` | `tk.cfg.more <累计字节数>` |
| `>tk.cfg.end <8位十六进制CRC>` | `tk.cfg.ok <规范JSON字节数> <CRC>` |
| `>tk.cfg.read` | `tk.cfg.begin <字节数>`，多行 `tk.cfg.data <base64>`，最后 `tk.cfg.end <CRC>` |

写入必须收齐长度、CRC正确、结构/范围/UTF-8都通过，才保存NVS `nabo_tk/cfg_v1`；这是带 `TKCF`/版本/长度/CRC 的二进制封装，载荷为规范JSON。成功提交后才切换UI模型，组数/名片数缩小时收敛当前索引。读回每轮输出一段，传输期间不自动休眠。网页在提交后自动读回，校验CRC并比较完整配置，核对一致才显示成功。

失败回复 `tk.cfg.err <固定代码>`，不回显拒绝的配置。常见代码：`size/json/utf8/depth/keys/number/version/groups/cards/name/label/key/media/text/card/crc/data/state/busy/line/timeout/test/memory/storage`。接收10秒无数据或总计60秒到期会取消；超长行、坏base64、错序/超量数据、重复begin、test模式写入都拒绝，当前生效配置不切换。读取损坏NVS记录时使用默认并报错，保留原记录，不擦库。

`>tk.test=1` 时拒绝配置写入，可读真实已保存配置；模拟动作不持久化。test不是整个NimBLE/NVS生命周期的只读锁。设置、蓝牙槽和配对密钥继续使用独立键，此功能不删除它们。

## 宿主验证与构建
