# Host contracts

Run `./tools/validate.sh --static`, or native Windows `./tools/validate.ps1 -Static`, from the repository root. Requires Node.js, Python 3 and a C11 host compiler; the codec tests do not need Pillow/NumPy or ESP-IDF.

- 29 Node tests: pure JS rules, boot/voice/skip timing, passkeys, cancellation, right-side modifiers, camera cadence, PPT timer, wake, FIFO replacement/ignoring old reconnects during pairing, real inline DOM button wiring in a VM, schema/client checks and production C protocol communication. Three deliberate rule mutations are caught. New checks cover the six requested groups, screenshot Esc, unmodified UP/RIGHT/DOWN on all four hosts, Edit Cmd/Ctrl+Z/C/A, and `withDefaultGroups` preserving cards without mutating input.
- 7 C probe tests: 4,000 input events compared against the JS classifier, uint32 timer wrap, exhaustive secure/subscription readiness, exact keyboard/consumer bytes, disconnected actions, navigation and leading-zero/cancel behavior.
- 8 sprite codec tests: known RLE/delta rows, corrupt/truncated data, bad bounds/palette/timestamps/CRC and exact production frame decoding within budget.
- 7 flash-guard tests: exact app hash/chip/size, partition map/MD5/flags, device security, flash capacity, the measured legacy layout and its smaller app boundary; tests never open a port.
- 4 F0 observer tests: embedded status parsing, privacy field allowlist, exclusion of simulated/disconnected memory samples, and keeping advertising time separate from full boot timing. Two optional comparison checks require physical short OK/long UP and reject stale/cancelled/zero prompt tokens. One reconnect-policy check covers 500/10000ms boundaries and uint32 wrap. The C library is explicitly unloaded before temporary-directory cleanup on Windows. Host policy checks do not prove real reconnect timing.
- `verify_golden.py` re-records1,710 steps byte-for-byte/by SHA256: original1,582 plus128 configured steps, ten pages/six keys/five connection events/four OS types. Defaults now follow the user's explicit request: Screenshot, Typeless, CapCut, WeRead, Douyin and Edit. C export matches the current JS table; retained screenshot/paste, Typeless and CapCut actions are unchanged.

The complete gate for this revision **PASSED:102 tests (29 Node+73 Python),1710 full replay steps,3 deliberate mutations caught, and the ESP-IDF6.0.2/F3 build**. Candidate `0.3.1-shortcuts-dev1` has not been flashed or published. Prior F3 dev3 passed100 checks; F2 had87 (27 Node+60 Python). The production JS client communicates with production C parser/protocol/storage through stdio, never a real serial port.

The new-default-groups button preserves cards in the current editor. Read the actual badge first, replace groups, then explicitly write and verify. Schema tests prove input preservation, retained cards and rejection of invalid configuration; they do not validate browser permission flow or physical app behavior. Real USB write/three readbacks on the existing dev3 are separate device-configuration evidence; see [configuration](../docs/CONFIGURATION.md). No firmware flash or NVS erase was needed.

`test_tk_model.py` compares complete production C state/effects/sleepDue for1,710 steps, including variable group/card counts, disabled families,64-character text, consumer keys and shrinking-index clamps. Three deliberate C mutations are caught. The adapter only converts the configuration ABI; JSON parsing/persistence/client behavior is independently tested end to end. Demo bonds exist only in host fixtures; production starts empty/disconnected.

F3 additionally covers all92 animation frames/indices/times/seeks/loops/bounds/CRC, compact-font equivalence, exact PCM playback/cancel/replay and the5ms key-tone envelope. Renderer tests use real fonts/LVGL, covering ten pages/dialogs, wide six-digit passkeys, QR changes, custom CJK fallback, welcome phases/tool animations and dirty/full pixel equality. New group names/labels have regenerated glyphs; host glyph presence is not physical LCD acceptance.

Native `validate.ps1 -Stage F3` or POSIX `validate.sh --f3` reconfigures first to fetch pinned LVGL/cJSON; use `-Stage F2` / `--f2` for separate F2 regression. Missing LVGL causes explicit static-only SKIP, not pass; missing cJSON fails. IDF6 does not support MSYS builds. C preview additionally needs Pillow: `python tools/render_toolkit_preview.py --f3`.

RAM NVS/NimBLE providers inject storage failures and synthetic peers to check commit-before-eviction, preservation on failure, F0 migration and staging cleanup. They do not prove RTOS concurrency or physical power-loss behavior. No host test opens a serial port. Physical acceptance is tracked in [validation](../docs/VALIDATION.md); host/build passes do not prove app response. The user confirmed screenshot invocation/cancellation and said WeRead/Douyin work on the current host after updating the old dev3 configuration. Phone versus desktop was not identified, so this is not per-platform or per-chapter/seek acceptance, nor device acceptance of the unflashed candidate.
