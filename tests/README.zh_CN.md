# 宿主契约测试

从仓库根运行 `./tools/validate.sh --static` 或 Windows 原生 `./tools/validate.ps1 -Static`。依赖 Node.js、Python 3、C11 宿主编译器；精灵解码测试不需要 Pillow/NumPy 或 ESP-IDF。

- 20 项 Node 测试：纯 JS 规则、开机/语音/跳过时间、配对码与取消、右侧修饰键、相机连拍节奏、PPT 计时、唤醒、FIFO 替换与新配对时拒绝旧设备回连、VM 内真实内联 DOM 按键接线，并捕获三项故意修改的规则。
- 7 项 C 探路测试：4,000 次输入与 JS 按键分类器逐项比较、uint32 计时回绕、认证/订阅就绪条件全组合、键盘/多媒体精确字节、断线行为、导航及配对码前导零/取消。
- 8 项精灵测试：已知 RLE/差分行、损坏/截断、边界/调色板/时间/CRC，以及正式包逐帧解码和预算。
- 7 项刷写保护测试：app 哈希/芯片/大小、精确分区及 MD5、标记、安全状态、Flash 容量、实测旧表和更小的 app 边界；测试不打开串口。
- 4 项 F0 采集器测试：嵌入日志行的状态解析、隐私字段白名单、排除模拟/未连接内存，以及不把广播计时当成全程重启计时。另有 2 项可选数字比较实验检查：只接受实体短 OK/长上拒绝，拒绝过期/取消/零令牌；1 项回连策略检查覆盖 500/10000 ms 边界及 uint32 回绕。Windows 下 C 库在清理临时目录前显式卸载；宿主策略通过不代表真机回连已达三秒。
- `verify_golden.py` 在临时目录重录 1,710 步，对三个文件逐字节及 SHA256 比较。包括原1,582步和128步自定义配置；覆盖10页、6键、5种连接事件和4 OS。默认HID表不变。

当前 **87项（27 Node +60 Python）**。F1原71项保留；F2增加7项Node配置/客户端检查、8项C配置/协议/存储检查、1项自定义中文渲染检查。生产JS客户端通过stdio与生产C协议/解析/存储代码端到端通信，没有打开真实串口。

`test_tk_model.py` 使用实际生产 C 模型，逐步比较全部1,710步的完整JSON状态、全部输出及sleepDue，含可变组数/名片数、平台空绑定、64字符文字宏、媒体键、缩减索引；三项故意C变异被抓到。轨迹适配器只转换配置ABI，JSON解析/持久化/客户端另由F2端到端测试验证。演示设备只在宿主注入，生产初始化无假绑定。

渲染器使用真实字体/LVGL头，检查十页/弹窗、六位宽数字、QR内容切换、自定义中文备用字形，逐像素比较脏刷新与全刷新。完整 `validate.ps1 -Stage F2` 或POSIX `validate.sh --f2` 先reconfigure取得锁定LVGL/cJSON再测。静态模式缺LVGL时显式SKIP，不能算通过；缺cJSON则明确失败。IDF6不支持MSYS构建。C预览另需Pillow：`python tools/render_toolkit_preview.py --f2`。

NVS/NimBLE 测试用 RAM 提供器注入写入/提交失败、合成地址和旧偏好，核验先提交后淘汰、失败保留、F0 迁移和暂存清理；不证明 RTOS 并发或真实 Flash 断电安全。真机验收见 `../docs/VALIDATION.zh_CN.md`。完整编译、宿主通过不等于 F1 真机通过；没有测试打开串口。
